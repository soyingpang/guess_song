# 現場版優化紀錄（2026-09-29）

## 已實作

- 四選一及快選選項改以正規化歌名去重；已抽中的歌名不會重複作為干擾項。篩選池不足時會從同語言的已批准歌曲補足；仍不足時主持頁會提示加歌，不會出只有一兩個答案的題。
- 主持只接受本題已顯示的選項答案，避免網路訊息直接提交未顯示歌名。
- 題庫列表只在展開時建立 DOM，預設 80 首一頁，可搜尋和載入更多；分類及已批准題庫結果按題庫版本暫存。
- Firebase 題目狀態只在內容變更時寫入，避免每次畫面重繪都寫入相同資料。
- 本地媒體播放或定位失敗時停止倒數，明確顯示「播放失敗」及恢復指引。YouTube 嵌入播放器亦接入官方 IFrame API 的播放錯誤及自動播放受阻事件；若 API 無法載入，原有 iframe 仍可播放，但無法回報該類錯誤。
- 主持和玩家的瀏覽器儲存被禁用或容量不足時，不再因未處理例外令頁面整體失效；主持頁會顯示儲存警告。
- 玩家頁 CSS 抽到 `player.css`，主頁增加共用 `game-core.js`；Service Worker 快取清單和資源版本同步更新至 `onsite-v4`。
- 停止呼叫遠距音訊廣播的現行入口。舊音訊函式仍留在 `app.js` 和 `player.js`，後續如要移除，須先隔離現場倒數、答題時窗與 PeerJS 資料後備的共用程式。
- Firebase 匿名登入及角色規則已在正式專案啟用，主持和玩家使用獨立身分。
- 主持手動新增的自訂歌曲可直接出題；線上歌單仍按來源審核。

## 已驗證

- `npm test`：共用選項邏輯、答案驗證及網站資源引用。
- `npm run test:rules`：本機 Firebase emulator 驗證主持、玩家、其他玩家及未登入身分的讀寫權限。
- 瀏覽器：3493 首正式題庫關閉時沒有題目 DOM；展開顯示 80 首，搜尋及載入更多正常；主持與玩家透過 Firebase 入房、答題、加分、開估正常；本地媒體失敗時狀態可見。
- `node --check` 對主持、玩家、Firebase 同步、共用邏輯、Service Worker 等程式通過；瀏覽器控制台未見主持或玩家頁 JavaScript error。

## 2026-09-30 發佈驗收

- GitHub Pages 已發佈 `onsite-v4`，正式題庫 3493 首；GitHub Actions 的 Pages 建站和 Web checks 均成功。
- Firebase Authentication 已啟用 Anonymous；正式 Realtime Database 已部署 `database.rules.json`，未登入讀房間收到 HTTP 401。
- 公開網址實測：主持開新房、玩家入房、主持加入自訂測試音訊、玩家答中、自動開估，兩邊均顯示 1 分。
- 只提交網站所需檔案；其餘本機研究檔案和未完成工作樹改動沒有上線。

## 使用前留意

- YouTube 影片下架、禁嵌入或廣告等情況仍需正式活動前試播。IFrame API 可回報 YouTube 已知錯誤，但廣告、網絡中斷及 API 本身無法載入時不一定會給出可靠事件。
